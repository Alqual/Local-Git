1. プロジェクト概要

本フェーズ（v2.0）の目的は、初期プロトタイプ（v1.0）で確認された「線形探索による性能低下」および「メモリ肥大化」の課題を解決することです。 生物の脳における「海馬（Hippocampus）」と「大脳皮質（Cortex）」の関係性を模した新しいアーキテクチャを採用しました。

2. 研究部門報告: 新規論理構成

2.1 Hippocampal Indexing (海馬インデックス)

短期記憶領域に、検索キーからニューロンIDへの「逆引きインデックス」を配置。これにより、属性検索の計算量を O(N) からほぼ O(1) へと劇的に削減しました。

2.2 Memory Consolidation (記憶固定化)

脳の睡眠サイクルと同様の機能を実装。 - Short-term Memory (STM): アクティブなニューロンのみをメモリ上に保持。 - Long-term Memory (LTM): 一定期間アクセスのないニューロンはディスク（JSONファイル）へシリアライズし、メモリを解放。 - Recall (想起): 必要時のみLTMからSTMへデータをリロードする。

これらの機能により、「無限に近いストレージ容量」と「高速なアクティブデータアクセス」の両立を目指しました。

3. 開発部門報告: 実装詳細

Python標準ライブラリのみを使用し、以下のコンポーネントを実装しました。

  • InvertedIndex クラス: 属性値ごとのIDセットを管理。
  • StorageCortex クラス: ファイルシステムを用いたLTM管理。
  • NeuroPlasticDB_V2 クラス: 上記を統合し、STM/LTM間のデータ移動（Consolidation/Recall）を制御。

コスト遵守状況: 追加ライブラリなし。コスト $0.00 を維持。

4.3 考察

インデックス導入により検索速度が安定し、ティアリング（STM/LTM）によりメモリ効率が最大化されました。 ただし、現行のLTM実装（1ファイル1ニューロン）は、データ数が数百万を超えるとファイルシステムの限界（inode枯渇など）に達する可能性があります。次フェーズではLTMの構造改善（LSM-Tree風の構造など）が推奨されます。

# チーム構成定義 (Team Definition)

## 1. 研究部門 (Research Department)
- **エージェント数**: 2名
- **役割**: 
  - 与えられたテーマに対し新規アイデアを調査企画する（論理レベル）。
  - 企画したアイデアの実現性を検証し、実現性が担保できることを目指す。

## 2. 開発部門 (Development Department)
- **エージェント数**: 2名
- **役割**: 
  - 研究部門が調査企画した論理レベルでの企画に関して実装レベルの実現性検証と試作を行う。
  - 試作が実装レベルの実現性を担保し、試作品の仕様書を作成することを目指す。

## 3. 品質実装部門 (Quality Implementation Department)
- **エージェント数**: 2名
- **役割**: 
  - 開発部門の提示する試作品の仕様書をベースに、実際の製品を設計・実装し、その後テストを実践する。
  - 設計実装された製品がテストを確実にクリアすることを目指す。

## 4. コスト部門 (Cost Department)
- **エージェント数**: 1名
- **役割**: 
  - 他3部門の活動のコスト検証を行う。
  - **重要**: 各エージェントの使用する各種ツール、ライセンス等、すべてのプロセスが「無料」であることを保証する。
  - 想定していない経費の発生を監視するとともに、その発生の原因となる活動を即座に停止させる。

---
**合計エージェント数**: 7名

# プロジェクトテーマ (Project Theme)

## テーマ: 新しいタイプのDB構造の検証と製品化
**ミッション**: 
1. 最近のトレンドとなるDB構成（NoSQL, NewSQL, Vector DB, Graph DBなど）を調査する。
2. 既存のトレンドよりも新しいタイプのDB構造を考案し、製品化する。

## 制約事項 (Constraints)
- **完全無料の保証**: 開発、調査、実装に使用する全てのツール、ライブラリ、環境はフリーライセンス（オープンソース等）であり、金銭的コストが一切かからないものに限定する。コスト部門はこの制約を厳格に管理する。

# Implementation Plan: 入力情報の量子化モック（Phase 4）

## 📌 概要
本フェーズでは、文字列（シンタックス）の単純な配列追加による「古典的バッファ管理」からの脱却を図ります。
ユーザーの入力情報やシステムの状態を、テキストストリングではなく高次元空間上のベクトルへと「量子化（Quantization）」し、「確率的・意味的な重みの重ね合わせ（Semantic Superposition）」として状態を維持するアーキテクチャの基礎を試作します。

## ⚙️ 設計思想 (Quantum-inspired Architecture)
1. **状態ベクトル（State Vector `|Ψ>`）による一元管理**
   過去のテキストログを文字列として配列にそのまま残す手法をやめ、対話全体・システム内部の文脈状態をひとつの高次元ベクトル（あるいは複数ベクトルの干渉テンソル）として保持します。
2. **情報の重ね合わせ (Superposition)**
   新しい入力が到着するたびに、その意味情報（Embedding）を既存のState Vectorに数学的に合成（加算・干渉・減衰付き重畳など）させます。これにより、過去の情報は「文字列としては消滅するが、意味の重み（振幅）や相対的距離感としては残存し続ける」という実質的なセマンティック無損失を実現します。
3. **観測による崩壊 (Measurement & Collapse)**
   SLM（推論エンジン）が推論を開始する直前という最も必要な瞬間においてのみ、State Vectorを「観測」します。そのベクトル（あるいはそこから導かれる確率分布）に基づいて外部ナレッジベースなどをスキャンし、直近のアテンションにもっとも合致する情報だけを限定的な文字列として実体化（Collapse）させてから、`small_lm_engine.py` に流し込みます。

## 🛠️ 具体的な実装ステップ
### [NEW] `quantum_controller.py` (配置先: `retrieval_lm/` 直下)

1. **Embedding（量子化器）モジュールの導入**
   - リソース消費が少なくVRAMを圧迫しない軽量な埋め込みモデル（例：`sentence-transformers/all-MiniLM-L6-v2` 等）をロードし、テキストをSemantic Vectorへ一意に「量子化」する仕組みを組み込みます。
2. **`QuantumState` クラスの作成**
   - 内部プロパティとして `self.state_vector` (Numpy配列またはTorch Tensor) を保持するメモリ管理クラスを実装します。
   - `update(input_vector)` メソッドを備え、過去の状態へ新しい入力ベクトルをどう重ね合わせるかのロジック（例：減衰係数αを用いた指数移動平均的なベクトルの足し合わせ演算）を実装します。
3. **観測（Measurement）ロジックの構築**
   - 保持し続けている `state_vector` を用いて、ダミーDB（辞書や文書群）とのコサイン類似度や干渉度合いを測定します。
   - 最も類似度の高い情報を確定的なテキストとして抽出し、「今観測された現実のコンテキスト文字列」としてSLMへ引き渡す処理を書きます。
4. **実験と検証**
   - 前回の古典的コントローラでは「文字列情報が多く、小規模LLMが幻覚（ハルシネーション）を見てしまった」複雑な連続質問に対してテストを行います。
   - 文字列ではなく「ベクトル推移の意味の集合」として抽出されたコンテキストが、より鋭く、ノイズを省いてSLMに正しい回答を与えられるかを検証します。

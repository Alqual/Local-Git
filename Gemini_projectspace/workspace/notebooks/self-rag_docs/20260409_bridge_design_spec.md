**対象**: ハイブリッド型無損失AIアーキテクチャの接続領域  
**作成日**: 2026-04-09  
**位置づけ**: `hybrid_architecture_experiment_plan.md` の Step 3 詳細化

## 構造の全体像（再掲）

```
                  ┌─────── 古典層 ────────────────┐
ユーザー入力 ──→ │  KVキャッシュ                   │
                  │  ・直近N トークンを完全保持      │
                  │  ・LLM が直接参照する           │
                  └────────┬──────────────────────┘
                            │ ① トリガー検知
                            │ ② 転送対象の選択
                            │ ③ 形式変換（テキスト→ベクトル）
                            ↓
                  ┌─────── ブリッジ層 ────────────┐
                  │  ClassicalToQuantumBridge       │
                  └────────┬──────────────────────┘
                            │ ④ 状態空間への合成
                            ↓
                  ┌─────── 量子層 ────────────────┐
                  │  LangevinState / LindbladState  │
                  │  ・意味のベクトル重ね合わせ       │
                  │  ・確率的散逸により時間を表現     │
                  └────────┬──────────────────────┘
                            │ ⑤ クエリ時に Collapse（抽出）
                            ↓
                  LLM（ステートレス推論エンジン）
```

## 取り組む順序と詳細

### B1: トリガー設計（いつ転送するか）

**優先度: 最初に決める（他の全設計が依存する）**

KVキャッシュが満杯になる「直前」を検知してブリッジを起動するプロトコル。

#### 設計選択肢

| 方式 | 説明 | メリット | デメリット |
|---|---|---|---|
| **A: 固定閾値** | トークン数が `THRESHOLD` を超えたらトリガー | シンプル・実装が最も容易 | 急峻な閾値処理（やや不連続） |
| **B: 滑らか転送** | トークン数が `WINDOW * 0.7` を超えたら常時少量送り続ける | グラデーションな転送で自然 | 転送頻度の制御が複雑 |
| **C: 重要度ベース** | 古いトークンのAttentionスコアが低下したら転送 | 意味的に最適 | Attention値の取得が必要（APIの制約あり） |

**第1版推奨: 方式A（固定閾値）**  
実装例:
```python
WINDOW_SIZE = 2048      # 古典層の最大トークン数
TRANSFER_KEEP = 1024    # 転送後に古典層に残すトークン数
TRANSFER_CHUNK = WINDOW_SIZE - TRANSFER_KEEP  # 転送するサイズ

if token_count(history) > WINDOW_SIZE - 200:  # 200トークンの余白
    overflow_text = extract_oldest(history, n=TRANSFER_CHUNK)
    bridge.transfer(overflow_text)
    history = history[-TRANSFER_KEEP:]
```

### B2: 選択設計（何を転送するか）

**優先度: B1の次（転送の質を決める）**

「溢れる情報のどの部分を量子層に送るか」を決める。

#### 設計選択肢

| 方式 | 説明 | メリット | デメリット |
|---|---|---|---|
| **A: 全量転送** | 削除するトークン全てを転送 | 無損失・実装容易 | ノイズも混入する |
| **B: 文単位圧縮** | 転送対象を文境界（`。`や`\n`）でまとめて1ベクトルに | 意味的に自然なまとまり | 文分割の処理が必要 |
| **C: 重要度フィルタ** | Attentionスコア上位の文だけを転送（Hebb的ゲート） | 信号品質が高い | 実装が複雑・Step 6 以降推奨 |

**第1版推奨: 方式B（文単位圧縮）**  
実装方針:
1. 転送対象テキストを文（`。`や改行）で分割
2. 各文を `SentenceTransformer.encode()` でベクトル化
3. 文単位で順次 `quantum_state.update()` へ送る

---

### B3: 変換設計（どの形式で転送するか）

**優先度: B2と並行して決める（意味の粒度の問題）**

テキスト→ベクトルへの変換における重要な設計パラメータ。

#### 主要な選択肢

| 選択肢 | 粒度 | 情報の保持量 | 計算コスト |
|---|---|---|---|
| **1文→1ベクトル** | 細かい | 高い（各文が独立して抽出可能） | 大（文数分のエンコード） |
| **N文→1ベクトル（スライディング）** | 中間 | 中 | 中 |
| **全転送テキスト→1ベクトル** | 粗い | 低い（段落全体の平均的な意味 ) | 小 |

**第1版推奨: 1文→1ベクトル方式（文数が多くなければコスト問題は小さい）**

#### 埋め込みモデルの選択

| モデル | 次元数 | 特性 |
|---|---|---|
| `all-MiniLM-L6-v2` | 384次元 | 軽量・英語中心。今回の実験で実績あり |
| `paraphrase-multilingual-mpnet-base-v2` | 768次元 | 多言語対応（日本語会話に有利） |
| `text-embedding-3-small` (OpenAI API) | 1536次元 | 高精度だがAPIコストが発生 |

**推奨: まず `all-MiniLM-L6-v2` で動作確認、日本語精度が必要なら多言語モデルへ移行**

---

### B4: 取り出し設計（クエリ時にどう使うか）

**優先度: B1〜B3の実装後（動作確認してから設計する）**

LLMが「古典層にない情報」を必要とした場合に量子層から情報を抽出（Collapse）するプロセス。

#### 動作フロー

```
LLM が応答を生成しようとする
    ↓
プロンプト構築時に「量子層への問い合わせ」を実行
    ↓
現在のユーザー入力を量子状態にエンコードし、
長期記憶（量子層）と干渉（コサイン類似度でTopK抽出）
    ↓
類似度上位N件のテキストをプロンプトの先頭に追加（Collapsed Context）
    ↓
LLM へ送信
```

#### 設計パラメータ

| パラメータ | 第1版候補 | 備考 |
|---|---|---|
| 抽出件数（TopK） | 2〜3件 | 少なすぎると効果なし、多すぎるとプロンプトが長くなる |
| 類似度閾値 | 0.3以上 | 低すぎると無関係なものが入る |
| 量子層の更新タイミング | ユーザー入力のたびに更新 | クエリも状態ベクトルに影響する（副作用あり） |

## 全体のリスクと対策

| リスク | 内容 | 対策 |
|---|---|---|
| **ノイズ混入** | 重要でない情報も量子層に蓄積 | Step B2 の選択フィルタを強化 (Step 6 のHebb的ゲート) |
| **Collapseの精度不足** | 量子層から的外れな情報が抽出される | 類似度閾値を調整、多段Collapseを実装 |
| **日本語の埋め込み精度** | `all-MiniLM` が日本語に弱い場合 | 多言語モデルに切り替え |
| **転送コスト** | 大量のテキストをリアルタイムにエンコードすると遅延 | バッチ処理化、またはバックグラウンドスレッドへ分離 |
| **状態の発散** | 量子層の散逸係数が合わず状態が不安定になる | Phase 14 の最適パラメータ（Langevin: μ=0.05, σ=0.02）を初期値に |

## 実装の推奨実施順

```
Week 1（週末）：B1 + B3 だけで最小動作版を作る
  → 古典層が溢れたトークンをベクトル化して量子層に送るだけ
  → まだ取り出し（B4）はせず、量子層に蓄積されるか確認

Week 2：B4 を加えてEnd-to-Endの動作確認
  → 量子層からCollapseした情報がLLMのプロンプトに入っているか確認

Week 3：B2 の文単位選択フィルタを追加して精度向上
  → ノイズ削減・抽出精度の向上を計測

Week 4 以降：B2-C + Step 6 のHebb的ゲートで高度化
```
